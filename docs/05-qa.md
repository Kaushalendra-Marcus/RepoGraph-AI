# 05 — Q&A Tab

## What it does
Stateful multi-turn chat about the analyzed codebase. Uses the full repo summary + graph + file summaries as context.

---

## Backend — QAAgent.ts

**Class:** `QAAgent`

**Constructor:**
```typescript
new QAAgent(provider: AIProvider, wsInfo: WorkspaceInfo, graph: DependencyGraph, summary: RepoSummary)
```

**Context strategy:** System prompt includes:
- Repo name and overview
- Full tech stack
- All key modules
- Entry points
- Top 20 most-connected files (by inDegree + outDegree)
- Architecture description

This context is set once at construction and reused for all turns.

**`ask(question: string): Promise<string>`**
- Appends user question to conversation history
- Sends full history to provider
- Appends AI response to history
- Returns response string

**`clearHistory()`**
- Resets conversation history to just the system message

**History limit:** Conversation history is not trimmed. If very long conversations cause token limit errors, the provider will throw — this is caught in `FileHandler.askQuestion()` and returned as an error message in chat.

---

## When QAAgent is created/reset

| Event | Action |
|-------|--------|
| Analysis complete (step 5) | New QAAgent created with full context |
| History restored | New QAAgent created with summary from record (no file summaries in context) |
| Provider saved (settings) | QAAgent re-created if analysis data exists |
| `clearChat` message | `qaAgent.clearHistory()` called (keeps same instance, clears turns) |

## Webview — Q&A tab

### HTML structure
```
#tab-qa
  #qa-empty         — shown before analysis (or if qaAgent not initialized)
  #qa-ready         — shown when qaAgent is ready
    #chat-history   — scrollable message list
    .chat-footer
      .quick-qs     — preset question chips
      .chat-row     — textarea + send button
```

### Quick question chips (hardcoded)
- "What does it do?"
- "Entry point?"
- "Auth?"
- "Key modules?"
- "How to run?"
- "DB/Services?"

### Key functions
```javascript
enableQA()           // Shows #qa-ready, hides #qa-empty
sendQ()              // Sends chat-input value as question
askQuick(q)          // Sets input value + calls sendQ()
addMsg(role, txt)    // Appends message bubble to chat history
addThinking()        // Adds animated typing indicator
removeThinking()     // Removes typing indicator
chatKey(e)           // Enter key handler (shift+enter = newline)
```

### Message flow
| Message | Action |
|---------|--------|
| `analysisComplete` | `enableQA()` |
| `analysisRestored` with `hasQA: true` | `enableQA()` |
| `answer` | `removeThinking(); addMsg('ai', payload.answer)` |

### Chat bubble markup
```html
<div class="chat-msg">
  <div class="av av-user">U</div>  <!-- or av-ai -->
  <div class="bubble user">message text</div>
</div>
```

### Thinking dots animation
CSS `@keyframes dpulse` — 3 dots, staggered 0.2s delay each.

## What to be careful about

- `QAAgent` is stateful — never re-use it across different analyses. Always create a new instance.
- `hasQA` in `analysisRestored` payload is `!!this.state.qaAgent` — if provider was not configured when history was saved/restored, it will be false and the Q&A tab shows the empty state.
- `clearChat` message calls `clearHistory()` on the existing agent — it does NOT destroy the agent. The system context stays.
